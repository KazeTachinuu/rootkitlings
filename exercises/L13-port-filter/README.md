# L13: Hide a Listening Port from procfs

## Mission

L11 and L12 hide data by copying the buffer, removing entries, and writing it
back. Port hiding uses a cleaner technique: rewind the seq_file write cursor so
the line is never emitted.

After hiding port 4444, connecting to it must still work even though the procfs
row is gone.

## What you will observe

A listener on the selected port continues accepting connections while its row
disappears from both IPv4 and IPv6 procfs tables. Removing the target makes the
same socket visible again. Unrelated ports never disappear.

## How procfs publishes TCP sockets

`/proc/net/tcp` and `/proc/net/tcp6` are generated by `tcp4_seq_show` and
`tcp6_seq_show`, once per connection. Each call writes one line into a
`seq_file` buffer:

```text
cat /proc/net/tcp
  |
  v
open + read /proc/net/tcp
  |
  v
tcp4_seq_show(seq, sk)       <-- called per connection
  |
  v
seq_printf(seq, " %d ...", port)
  |
  v
seq->count advances by the bytes written
```

`seq->count` is the write cursor. It tracks how many bytes have been written
into the output buffer.

If you save `seq->count` before the function runs and restore it afterwards, the
line is erased. No buffer copying, no memmove; the output simply shrinks.

## The rewind trick

```c
// Entry: save the cursor position before tcp4_seq_show writes
data->saved_count = data->seq->count;

// Return: if this port should be hidden, rewind the cursor
if (port_matches)
    data->seq->count = data->saved_count;
```

This works at the seq_file abstraction level. L11 and L12 work at the raw buffer
level (copy, modify, write back). Here the kernel does all the buffering; you
just undo the last write.

## Extracting the port

The second argument to `tcp4_seq_show` is a `struct sock *`. Extract the source
port through the `inet_sock` layer:

```c
struct inet_sock *inet = inet_sk(data->sk);
unsigned short sport = ntohs(inet->inet_sport);
```

`inet_sport` is in network byte order. `ntohs` converts to host order. Convert
the integer to a decimal string with `snprintf`:

```c
char port_str[8];
snprintf(port_str, sizeof(port_str), "%u", sport);
```

Compare that string against the target list.

## Protect the header row

The first call to `tcp4_seq_show` passes `SEQ_START_TOKEN` (`(void *)1`) as the
sock pointer. This is the header row ("sl local_address ...").

If you cast `SEQ_START_TOKEN` to `struct sock *` and dereference it, you oops
the kernel. Always check:

```c
if (data->sk == SEQ_START_TOKEN)
    return 0;  // header row, skip
```

Both `tcp4_seq_show` and `tcp6_seq_show` are regular functions, not syscall
wrappers. Arguments are directly in `regs->di` (seq_file) and `regs->si` (sock).

```console
$ ./rklings run L13
```

Inside the guest, start a listener and note the hex port (4444 decimal is
0x115C):

```console
root@victim:~# nc -l -p 4444 &
root@victim:~# grep -i ':115C ' /proc/net/tcp
  0: 00000000:115C 00000000:0000 0A ...
```
